# Localization Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or
> superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship the app in English, Simplified Chinese, Traditional Chinese and Japanese, with no key left
untranslated, and with the platform-specific traps handled rather than discovered in review.

**Architecture:** resx resources with English as the neutral language and one file per additional language,
accessed through a strongly-typed class generated during the build. A `LanguageService` owns
`CultureInfo.CurrentUICulture`, persists the user's choice, and rebuilds the shell so every string refreshes
at once (including Shell tab titles, which cannot bind to a change notification).

**Spec:** `docs/superpowers/specs/2026-09-28-ibe-barcode-scanner-design.md`

## Platform traps this plan handles explicitly

1. **iOS ignores undeclared locales.** Without `CFBundleLocalizations` (and a `CFBundleDevelopmentRegion`),
   the app falls back to English no matter what resources exist. Silent, and easy to ship.
2. **No Visual Studio, no designer.** The strongly-typed resource class is normally generated by the IDE;
   a command-line build has to generate it via MSBuild `StronglyTypedLanguage` metadata. Without it, every
   `AppResources.X` reference fails to compile.
3. **Android app name and iOS permission prompts are not resx.** The launcher label comes from
   `values*/strings.xml`, and the camera/photo/NFC prompts come from `InfoPlist.strings` per `.lproj`.
4. **Chinese script matters more than region.** `zh-CN`/`zh-SG` must map to `zh-Hans` and `zh-TW`/`zh-HK` to
   `zh-Hant`, so the language resolver maps regions to scripts instead of hoping for an exact culture match.

---

### Task 1: String resources — DONE

**Files:** `src/IBEBarcode.Scanner/Resources/Strings/AppResources.resx` (+ `.zh-Hans`, `.zh-Hant`, `.ja`)

- [x] 90 keys per language covering the whole UI: titles, scan instructions, every result field, actions,
      history, NFC states, about text and language names.
- [x] Identical key sets in all four files, no empty values.
- [x] Language names appear as endonyms (`English`, `简体中文`, `繁體中文`, `日本語`) so the picker is usable
      whichever language the user currently sees.
- [x] Technical values that are Latin script regardless of locale (ISBN-13, NFC, MIT) stay identical, and are
      allow-listed in the test rather than tolerated by a fuzzy threshold.

### Task 2: Build-time accessor generation — DONE

**Files:** `src/IBEBarcode.Scanner/IBEBarcode.Scanner.csproj`

- [x] `<NeutralLanguage>en</NeutralLanguage>` so an unsupported device culture falls back to English.
- [x] `EmbeddedResource` metadata for `AppResources.resx` with `StronglyTypedLanguage`, `StronglyTypedNamespace`,
      `StronglyTypedClassName` and an `$(IntermediateOutputPath)` output path, per the .NET MAUI 10
      documentation.
- [x] Localized files are embedded as satellites by the SDK's default resx handling, without generating code.

### Task 3: Language selection and application — DONE

**Files:** `src/IBEBarcode.Scanner/Services/{LanguageService.cs,SettingsService.cs}`, `App.xaml.cs`

- [x] Applied in the `App` constructor, before any page or shell exists, so the first window is already in the
      right language.
- [x] Device language is honoured when it is one we ship; region-only Chinese cultures map to the right script.
- [x] The choice is persisted in `Preferences` (not a database) and offered as "match device" plus the four
      languages.
- [x] Changing language rebuilds the shell, which refreshes every bound string and the tab titles.
- [x] Numbers and dates use `CultureInfo.CurrentCulture`, so timestamps localize too.

### Task 4: Platform-level strings — DONE

**Files:** `Platforms/Android/Resources/values*/strings.xml`, `Platforms/iOS/Resources/*.lproj/InfoPlist.strings`, `Platforms/iOS/Info.plist`

- [x] Android launcher name localized in four `values*` folders.
- [x] iOS permission prompts (camera, photo library, NFC) localized in four `.lproj` folders.
- [x] `CFBundleLocalizations` and `CFBundleDevelopmentRegion` declared.

### Task 5: Tests that keep it honest — DONE

**Files:** `tests/IBEBarcode.Scanner.Core.Tests/LocalizationResourceTests.cs`

- [x] Key sets identical across files, with the missing/extra keys named in the failure message.
- [x] No empty values anywhere.
- [x] Chinese and Japanese files must be genuinely translated, with an explicit allow-list for the handful of
      values that are Latin script or endonyms by design.
- [x] The test locates the repository by walking up for `IBEBarcodeScanner.slnx` and no-ops if it cannot, so it
      never turns into a false failure in a different layout (with a comment saying so).
